# Midas M32 / M32R / M32C (and M32 LIVE / M32R LIVE): multitrack recording facts

The M32 family uses the same routing architecture and firmware family as the Behringer X32 (see x32.md). It has its own Klark Teknik cards:
- **DN32-USB**: USB only. Older M32 and M32R units shipped with it.
- **DN32-LIVE**: USB plus two SD slots. Fitted to the M32 LIVE and M32R LIVE.
- **XUF**: the X-UF equivalent. The first M32 manual calls the card "XUF".

Source labels: [M-x] = Midas, Klark Teknik or Music Tribe document (maker; some read through third-party hosts, noted). [S-x] = secondary.

## 1. USB audio to a computer

| Item | DN32-USB | DN32-LIVE |
|---|---|---|
| Channels | "32 x 32-channel USB audio interface" [M-1] | USB in/out "32, 16, 8, 2" duplex [M-2] |
| Sample rate | "24-Bit, 48 kHz" [M-1]; 44.1 kHz not stated for DN32-USB (unknown) | follows the console clock, 44.1 / 48 kHz (SD spec line) [M-2] |
| Bit depth | 24-bit [M-1] | 24-bit on USB: unknown, not stated (SD is 32-bit) |
| Connector | "USB 2.0"; plug type not stated (unknown) | "USB 2.0 high speed, type-B (audio/MIDI interface)" [M-2] |

- The console's rear "USB Type B" port is "for remote control" only [M-2].
- The top-panel "USB Type A" port is for "Audio and Data Import / Export" [M-2].

## 2. Driver status

- **macOS:**
  - DN32-USB: "Class-compliant USB design compatible with Mac OS X CoreAudio - no driver required" [M-1].
  - DN32-LIVE: listed for "Mac OSX DAW applications (Intel CPU only, no PPC support, CoreAudio)", Mac OS X 10.6.8 to 10.12 [M-2].
  - The "Intel CPU only" wording dates from the PowerPC era. It is not a statement about Apple silicon, which is unknown.
- **iOS / iPadOS:** unknown. No Midas or Klark Teknik document found. The "class-compliant" wording [M-1] suggests a generic USB Audio Class device, but that is inference.
- **Windows:** ASIO driver ("Ultra-low latency ASIO drivers" [M-1]; "ASIO, WASAPI and WDM" [M-2]).
- **Mode switch:** set the channel count on the console's Setup > Card page. Options are 32, 16, 8 or 2 each way per the spec [M-2]. The mode list names (32/32, 16/16, 32/8, 8/32, 8/8, 2/2) are confirmed for the X32 cards only. The exact M32 menu list is unknown (our inference is that it matches).

## 3. Recording without a computer

- **DN32-LIVE SD** (maker spec [M-2]):
  - 2 SD/SDHC slots, FAT32, 1 to 32 GB each.
  - 32, 16 or 8 channels.
  - 44.1 / 48 kHz (console clock), "32 bit PCM".
  - "WAV 8, 16 or 32 channels", uncompressed multi-channel (**poly**) WAV.
  - Maximum recording time: 200 min (32 ch, 44.1 kHz, two 32 GB cards).
  - Use class 10 media for 32 channels; class 6 is enough for 8 or 16.
  - Optional CR123A battery protects files in a blackout.
- **Top-panel USB stick recorder:** stereo.
  - "Stick must be formatted for FAT file system. Maximum record time is approximately three hours for each file, with a file size limit of 2 GB. Recording is at 16-bit, 44.1 kHz or 48 kHz depending on console sample rate" [M-2].
- **DN32-USB:** no onboard recording.

## 4. Recording settings

- **Sample rate and sync:** Setup screen (as on X32: Setup > Config/Global; a rate change needs a reboot on X32 [see x32.md B-1]). An M32-specific source for the reboot requirement is unknown.
- **Card channel count and SD control:** Setup > Card page. The M32 LIVE QSG says "card: This screen selects the input/output..." [M-2]. Record/Play channel-routing presets like X-LIVE's are not described in the M32 LIVE QSG we read: unknown on M32 (our inference from the shared firmware family is that they exist).
- **Bit depth:** fixed, as on X32. **Format:** poly WAV.

## 5. Routing

The ROUTING tabs on M32 LIVE are home, out 1-16, aux out, p16 out, card out, aes50-a, aes50-b and xlr out [M-2]. The M32 manual's card out text is the X32 text with "XUF" for the card [M-3].

### Method A: 8-channel blocks (maker-documented)

- **Path:** ROUTING > **card out**. Rotary controls 1 to 4 each pick an 8-channel block for card outputs 1-8, 9-16, 17-24 and 25-32.
  - "Adjust the first rotary control to select an 8-channel signal path that will be sent to the first eight channels..."
  - "Repeat the process with controls 2-4" [M-3].
- **Block choices** [M-3]:
  - Local 1-8 / 9-16 / 17-24 / 25-32
  - AES50-A 1-8 … 41-48
  - AES50-B 1-8 … 41-48
  - Card 1-8 … 25-32
  - Out 1-8, Out 9-16
  - P16 1-8, P16 9-16
  - Aux 1-6/Mon
- **Local and AES50 blocks are raw inputs** (after the preamp, before the channel strip).
- **Buses, main mix or tapped direct outs:** stage them in **out 1-16** or **p16 out** with a tap per slot, then pick `Out 1-8`, `Out 9-16`, `P16 1-8` or `P16 9-16` on card out [M-3; S-1].

### Method B: user routing (User In / User Out), firmware 4.x (secondary)

- The X32 and M32 share firmware generations. ControlBooth users report updating "3 X32 and 2 M32" to firmware 4.02 [S-2].
- A behringer.world thread about an M32 with an ADAT card was answered with the same X32 firmware 4 routing advice [S-1].
- No Midas document found that names USER IN and USER OUT tabs on M32.
- Treat M32 user routing as probably identical to X32 (48-slot User Out, 32-slot User In, no tap points on User Out itself, built blocks picked on card out). Confidence: secondary.

### Which method to use

Same advice as x32.md:
- Raw input blocks for a straight 32-track recording.
- User Out to pick or reorder single sources.
- Out 1-16 or P16 staging when you need main L/R, buses or a per-track tap.

### Playback for virtual soundcheck

- Switch channel inputs to Card blocks on ROUTING > home.
- On card input, channel gain becomes a digital trim; real preamp gain is on Setup > preamps (documented for X32 [x32.md B-1]; for M32 this is our inference from the shared design, not a Midas statement).

## 6. Tap points

- **Out 1-16 / P16 slots:** "Input", "Pre-EQ", "Pre-Fader", "Post-Fader", per slot. The M32 manual (P16 Out section) says: "This determines where in the audio signal path the source is 'tapped'..." [M-3].
  - Newer firmware tap names such as "Input/LC" and "+M" mute-following variants come from X32 forum sources [see x32.md S-2, S-9]. Exact M32 names: unknown.
- **Card out Local/AES50 blocks:** raw, with no tap choice (per block).
- **Analog gain vs digital trim:**
  - The headamp gain (local, or a DL16/DL32 stage box over AES50) is before the record feed.
  - Channel trim, HPF and processing are after it.
  - Phantom power is on the source/preamp.
- **Shared stage box (DL16/DL32 with two consoles):** whichever console holds headamp control changes the recorded level. A gain-compensation feature on M32: unknown (none found).

## 7. Gotchas

- **The card is required.** No multichannel USB audio without DN32-USB, DN32-LIVE or XUF.
- **Blocks of 8 on card out.** Mixed or partial sets need User Out (firmware 4.x) or staging.
- **DN32-LIVE SD is 32-bit poly WAV,** which needs splitting. SDXC above 32 GB is not supported.
- **The Mac support list stops at OS X 10.12 in the LIVE QSG.** Newer macOS support is unknown from that document; the class-compliant claim [M-1] suggests it works without a driver.
- **iPhone/iPad:** unknown from maker.
