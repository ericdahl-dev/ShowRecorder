# Behringer X32 family (X32, Compact, Producer, Rack, Core): multitrack recording facts

Applies to every X32 model with the expansion card slot. The card decides what reaches a computer:
- **X-USB**: the factory card for years, USB only. Now "Legacy" (no longer made).
- **X-LIVE**: USB plus two SD/SDHC slots for recording without a computer. The current card.
- **X-UF**: an older card with USB and FireWire. Discontinued.

Source labels: [B-x] = Behringer/Music Tribe document (maker). [S-x] = secondary (forum, retailer, third-party host).

## 1. USB audio to a computer

| Item | X-USB | X-LIVE | X-UF |
|---|---|---|---|
| Channels in/out | 32 x 32 (modes 32, 16, 8 or 2 each way) [B-3][B-4] | 32 x 32 (32, 16, 8, 2 duplex) [B-5][B-6] | 32 x 32 over USB 2.0 or FireWire [S-1] |
| Sample rate | 44.1 / 48 kHz [B-4] | 44.1 / 48 kHz, follows the console clock [B-6] | unknown (24-bit stated) [S-1] |
| Bit depth | 24-bit [B-4] | 24-bit on USB; SD files are 32-bit (see 3) [B-6] | 24-bit [S-1] |
| Connector | USB 2.0 High Speed; plug type not stated in the X-USB guide (unknown, probably Type B) | "USB 2.0 high speed, type-B (audio/MIDI interface)" [B-6] | unknown |
| Round-trip latency | about 14 ms typical [B-4] | unknown | unknown |

- The console's own rear "USB Type B" port is "for remote control" only. Audio goes through the card's port [B-1].
- The top-panel "USB Type A" port is for "audio and data export/import", which means the stereo USB-stick recorder (see 3) [B-1].

## 2. Driver status

- **macOS:**
  - X-USB: "CoreAudio compatible and thus works with low-latency on Mac computers without any additional driver installation" [B-2][B-4].
  - X-LIVE: "CoreAudio compliant and therefore does not need a driver for use on Mac computers" [B-6].
  - The maker's OS lists are old: the X-USB guide lists Mac OS X 10.7 to 10.9 (10.6.8 limited to 16 x 16) [B-4]; the X-LIVE QSG lists Mac OS X 10.6.8 to 10.12 [B-6]. No maker document names a current macOS or Apple silicon.
  - Confidence: "no driver" confirmed by maker; current macOS versions unknown from maker documents.
- **iOS / iPadOS:** unknown. No Behringer document lists iOS or iPadOS for X-USB or X-LIVE audio. The X-LIVE page mentions iPad apps for remote control only, not audio [B-5].
- **Windows:** needs the Behringer ASIO driver from behringer.com [B-2][B-4][B-6]. The X-LIVE page offers the "X-LIVE USB audio" driver, v5.72.0 [B-5].
- **Mode switch:** set the USB channel count on the console at **Setup > Card**. The options are 32/32, 16/16, 32/8, 8/32, 8/8 and 2/2 [B-2][B-6]. There is no separate class-compliant mode switch.
  - The first number is channels to the computer: "32 in / 8 out" is for "many input channels but only a few output channels for monitoring", and "2 in / 2 out" is "for recording just the main stereo mix" [B-6]. A card left at 8/8 or 2/2 sends only 8 or 2 channels to the recorder.

## 3. Recording without a computer

- **X-LIVE SD recorder** (maker spec [B-5][B-6]):
  - 2 SD/SDHC slots, FAT32, 1 to 32 GB per slot. "SD cards up to 2 GB and SDHC cards up to 32 GB are officially supported" [B-6].
  - Sessions of 8, 16 or 32 channels.
  - "44.1/48 kHz / 32-bit PCM WAV files", stored as one uncompressed **multi-channel (poly) WAV** per session [B-6].
  - Maximum session: 200 min (32 channels, 44.1 kHz, two 32 GB cards). The product page says "3 hours and 20 minutes" [B-5].
  - A session can span from card 1 to card 2. The product page says "more than 12 hours of 8-track recording time non-stop" [B-5].
  - Use class 10 media for 32 channels; class 6 is enough for 8 or 16 [B-6].
  - Up to 100 markers. Optional CR123A battery protects files in a blackout [B-6].
  - Split the poly WAV into per-channel files with Audacity, a DAW, or the behringerwiki notes [B-6].
- **Top-panel USB stick recorder** (every X32): stereo only. The console's FAT stick limits a file to 2 GB, "about 3 hours of stereo recording". "The recording will be done as 16-bit WAV file with the selected sample frequency of the console" [B-1 §5.17]. (Corrected 2026-11-06: an earlier version said the X32 manual does not state the bit depth.)
- **X-USB and X-UF:** no onboard recording.

## 4. Recording settings

- **Sample rate and clock:** **Setup > Config** (old manual, which also calls it Setup > Global). Changing the rate needs a reboot. A red square at the top of the screen means a sync problem [B-1].
- **Card channel count:** **Setup > Card**, for both USB and the X-LIVE SD channel count [B-2][B-6]. On X-LIVE this page also chooses:
  - the playback source (SD or USB)
  - which SD slot records
  - the "Channel Routing" preset: Record, Play or Automatic [B-6].
- **Bit depth:** fixed. USB is 24-bit [B-4]; X-LIVE SD is "32 bit PCM" [B-6]; the USB-stick recorder is 16-bit WAV [B-1]. No option found.
- **Format:** X-LIVE writes multi-channel WAV only [B-6].
- **Clock source:** "Synchronization and Sample Rate settings for the console can be adjusted on the Setup/Config page" [B-1]. The list of clock sources is not quoted here (unknown).

## 5. Routing

There are two methods. Method A works on every firmware. Method B needs firmware 4.0 or later.

### Method A: 8-channel blocks on the Card Out tab (maker-documented)

- **Path:** press ROUTING, go to the **card out** tab, and turn encoders 1 to 4 to pick the 8-channel block for card outputs 1-8, 9-16, 17-24 and 25-32. Press each encoder to confirm [B-1 §7.4.5].
- **Block choices** [B-1]:
  - `Local 1-8`, `Local 9-16`, `Local 17-24`, `Local 25-32`
  - `AES50-A 1-8` through `AES50-A 41-48`
  - `AES50-B 1-8` through `AES50-B 41-48`
  - `Card 1-8` through `Card 25-32`
  - `Out 1-8`, `Out 9-16`
  - `P16 1-8`, `P16 9-16`
  - `Aux 1-6/Mon`
- **Local and AES50 blocks are raw inputs**, taken after the preamp and converter but before any channel processing. A channel's EQ, dynamics, fader or its own source choice does not affect them.
  - Maker: "the Card outputs may use any of the available signal sources in the console (local or AES50) for recording independently", and "all signals are run from the mixer's preamps directly to the multi-track recording machine" [B-1 §6].
  - Secondary: KMaxwell, "coming to the CARD before any processing on the channel at all", same with X-LIVE [S-2].
- **To record buses, the main mix or processed channels**, stage them first and then send that staging block to the card.
  - Stage on the **analog out** tab (Out 1-16), the **p16 out** tab (Ultranet 1-16) or the **aux out** tab.
  - Each slot picks a category: Main (LRC), Mix Bus, Matrix, Direct Out (any of the 32 channels), Monitor, Talkback, and so on.
  - Each slot then picks a tap point (see 6).
  - Then choose `Out 1-8`, `Out 9-16`, `P16 1-8` or `P16 9-16` on the card out tab [B-1; S-3 pvannatto: "use the Out 1-16 and Ultranet screen ... to assign the DirChan Out with taps to make up the blocks of 8. Then on the Card screen, assign the respective blocks"].
- **Block sizes:** card and AES50 outputs work in blocks of 8. The XLR out tab works in blocks of 4 [B-1].

### Method B: user routing, firmware 4.0 and later (secondary sources only)

- **What it is:** firmware 4 added **USER IN** and **USER OUT** tabs under ROUTING. In each one you choose a source for each single slot, which builds custom blocks of 8.
  - User Out has 48 slots [S-6 "outputs (1-48)"]. User In has 32 slots [S-5].
  - A third-party copy of the firmware 4.00 release notes (2019-11-13) reads: "point to point user routing, 4 input and 6 output banks (32 in / 48 out)" [S-10]. Behringer's own 4.00 notes could not be found; the X32 product page lists only the 4.15 notes (checked 2026-11-06).
  - You then pick those blocks (for example `User Out 1-8`) on the card out tab instead of fixed blocks [S-2][S-4][S-6].
  - Official firmware 4.0 notes describing it were not found. The 4.15 release notes mention "User Routing" by name ("HA safe flags not working correctly with User Routing") [B-7], which confirms the feature exists.
- **What a User Out slot can pick** [S-3][S-6][S-8]:
  - individual physical inputs (Local, AES50 A/B, Card)
  - the virtual outputs: Out 1-16, Ultranet/P16, Aux Out
- **No tap point on User Out itself.** One forum moderator: "Tap points are only available on the routing patching screens (Out 1-16, Aux Out, Ultranet (also called P16))" [S-3].
  - To put a channel direct out, bus, main or matrix at a chosen tap into a User Out slot, first patch it, with its tap, into an Out 1-16 or P16 slot.
  - Then point the User Out slot at that Out or P16 slot.
- **Example (forum):** User Out 1-8 = Local 1-3 plus AES50-A 1-5. Then choose `User Out 1-8` on card out [S-5 describes the same idea for User In].
- **Physical outputs are still blocks:** "Physical outputs (AES50, XLR Out, Card) are still in blocks of 4/8" [S-4 pvannatto].

### Which method to use

- **Raw multitrack of 8, 16, 24 or 32 local or stage-box inputs in order:** Method A with Local or AES50 blocks. This is the simplest, and the tracks are not affected by channel processing.
- **Fewer than 8 from a block, inputs mixed from local and stage box, or reordered tracks:** Method B (User Out).
- **Main L/R, buses, matrices, or a different tap per track:** stage them in Out 1-16 or P16 with per-slot taps, then send those blocks to the card (Method A), or pick the staged slots one by one in User Out (Method B).

### Default routing and playback

- **Factory default card out:** unknown. No maker document states it. The manual says only that "Input Channels 1-32 are pre-configured to use the first 32 input signals" [B-1], which is the channel source, not the card out. Guides should tell readers to check ROUTING > card out rather than assume a default.
- **Playback for virtual soundcheck:**
  - Route channel inputs to `Card 1-8` and so on with the ROUTING **home** tab. "The 32 card inputs can be used as alternate sources for the two input fader layers, switchable in banks of 8" [B-1 §7.4.5].
  - The maker describes the use: "It is also possible to run a virtual sound check of all 32 input channels by recording them directly to a computer during a brief line check" [B-1 §6][B-6].
  - In 16/16 mode the maker's suggested overdub setup puts the 16 live inputs on channels 1-16 and the card returns on channels 17-32 [B-1 §6][B-6].
  - X-LIVE adds Record and Play input presets on Routing/Home. Pick 'Record' or 'Play' with the 6th encoder, then flip between them at Setup > Card > Channel Routing, or set 'Automatic' to follow the transport [B-6].
  - With a channel set to Card, its Gain control becomes a ±12 dB digital trim. Phantom and gain then live on **Setup > Preamps** [B-1].
- **Aux returns:** "Aux Return Channels 1-8 are pre-configured to use the 6 aux input signals, and the two USB playback outputs" (the stereo USB-stick player) [B-1]. Forums also mention "aux remap" to card channels [S-2].

## 6. Tap points for the record feed

- **Card out Local/AES50 blocks:** raw input after the analog preamp and A/D, before the channel. Per block, with no tap choice [B-1][S-2].
- **Analog out (Out 1-16), p16 out and aux out slots:** a tap point per slot. The maker manual text lists **Input, Pre-EQ, Pre-Fader, Post-Fader** for the analog out and P16 tabs [B-1 §7.4.2-7.4.4]. (An analog-out screenshot in the same manual shows "Pre EQ / Post EQ / Pre Fader / Post Fader"; the numbered steps are the clearer source.)
  - Correction 2026-11-06: an earlier version called the block diagram's "Pre HP/Pre Gate/Post Gate/Pre EQ/Post EQ/Pre Fader/Post Fader/Post Pan" list insert/bus taps. In the diagram that list sits on each channel's **mix-bus sends**, not on outputs. The channel's feeds into the output patch are drawn as "PRE LOW CUT OUT" and "POST FADER OUT" [B-1 block diagram]. Don't present the long list as record taps.
  - Later firmware renamed and extended the taps:
    - A forum moderator names an **"Input/LC"** tap: "tapped after the low cut" [S-2 pvannatto].
    - A blog describes **"+M"** variants that follow the channel mute [S-9, search snippet only, not read].
    - The exact current list on firmware 4.x is unknown from a maker source.
- **Per channel or global:** per output slot, so each slot can use a different tap.
- **Analog gain vs digital trim:**
  - Mic gain and +48 V are on the preamp (the source), so they affect Local or AES50 card feeds.
  - The channel's low cut (HPF), EQ, dynamics and fader do not affect a raw Local or AES50 card feed [B-1 §6].
  - When a channel's source is the card, its Gain knob becomes "a +/- 12 dB digital trim for the interface card signal, without direct access to any head amp"; preamps are then set on Setup > preamps [B-1 §6].
  - The maker warns: "the mic preamp gain (also for recording) will be controlled from the FOH console, and Gain changes during the show can be heard in the recording" [B-1].
- **Shared stage box (S16/SD8 with two consoles):**
  - The record feed is taken after the stage box's headamp, so whoever controls headamp gain changes the recorded level.
  - Gain only follows HA remote control; the 4.15 notes mention "HA safe flags" with User Routing [B-7].
  - No gain-compensation feature was found in X32 documents: unknown.
  - Confidence: maker for "gain changes are heard in the recording"; unknown for gain compensation.

## 7. Gotchas

- **The card is required for multitrack.** Without X-USB, X-LIVE or X-UF there is no multichannel USB audio. The rear USB-B port is control only [B-1].
- **Card outs are blocks of 8.** Sending main L/R or buses means staging through Out 1-16, P16 or User Out first.
- **Channel source ≠ card source.** Re-sourcing a channel strip does not change what Local blocks send to the card. A forum user recorded silence on duplicated channels because of this [S-2].
- **X-LIVE SD writes one big 32-bit poly WAV,** which needs splitting. SD cards above 32 GB (SDXC) are not supported [B-6].
- **The iPhone/iPad path is undocumented.** The cards are CoreAudio class compliant on Mac (maker), which suggests generic USB Audio Class compliance, but there is no maker statement for iOS: unknown.
- **The card is bus or self powered:** unknown. The console is mains powered, so an iPhone should not need to power it (inference, not sourced).
- **Changing the sample rate needs a console reboot** [B-1].

## Gaps

Leave these out of the guide, or label them plainly:
- **iPhone / iPad with X-USB or X-LIVE:** no Behringer statement. Say "not tested yet" until a real Take is recorded.
- **Current macOS and Apple silicon:** the maker says "no driver", but its OS lists stop at 10.9 (X-USB) and 10.12 (X-LIVE). Don't name a macOS version as supported by Behringer.
- **User routing (User In / User Out):** no Behringer manual page. The menu, the 48/32 slot counts and "no tap on User Out" are secondary. Present it as "firmware 4.0 and later, per user reports", or check it on a console first.
- **Firmware 4.x tap names** ("Input/LC", "+M" variants): secondary. Use the maker list Input / Pre-EQ / Pre-Fader / Post-Fader.
- **Factory default card out:** unknown. Tell readers to check ROUTING > card out.
- **Clock source list** on Setup > Config: not quoted. Don't list options.
- **X-UF:** retailer specs only. **X-LIVE round-trip latency:** unknown.
- **Gain compensation for a shared stage box:** none found.
